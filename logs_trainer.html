📜 Как читать логи, когда их слишком много

⭐ Интерактивный гайд по материалу Habr — методология, команды Linux/Windows, инструменты и тесты для самопроверки.

📖 1. Основы: уровни логирования и стратегия поиска

🎚️ Уровни важности (от INFO до FATAL)
  • INFO – штатная работа
  • DEBUG – детали для разработчика
  • WARN – возможная проблема
  • ERROR – ошибка, но сервис жив
  • FATAL/CRITICAL – критический сбой компонента
  • TRACE – слишком подробно (осторожно на проде)
Stack trace
Рамка поиска
🧠 С чего начинать разбор (правило 5 минут)
  1. Когда началась деградация?
  2. Где стала заметна? (nginx / app / БД)
  3. Какой компонент ближе к симптому?
  4. Какие журналы относятся к цепочке?
  5. Идём от симптома: nginx → app → БД → очередь → ОС
# Пример рамки поиска в Linux
journalctl --since "2025-03-14 14:30" --until "2025-03-14 15:00" -u myapp.service

🐧 2. Linux: journalctl, grep, контекст и статистика

📋 journalctl – главный инструмент systemd
# Последние 200 строк сервиса
journalctl -u nginx -n 200 --no-pager
# Фильтр по времени и приоритету (warning..alert)
journalctl -u myapp -p warning..alert --since "1 hour ago" --no-pager
# Сравнить текущую и прошлую загрузку
journalctl -b -u myapp.service --no-pager
journalctl -b -1 -u myapp.service --no-pager
# Сообщения ядра (OOM, I/O ошибки)
journalctl -k --since "1 hour ago" | grep -Ei 'oom|killed process|segfault'
🔎 grep с контекстом и поиск по каталогу
# grep с 20 строками после и 10 до
grep -n -A20 -B10 'timeout' /var/log/myapp/app.log
# Рекурсивно по всем .log файлам
grep -Rni --include='*.log' 'request_id=abc123' /var/log/myapp/
# Поиск в сжатых логах
zgrep -ni 'exception' /var/log/myapp/app.log*.gz
📊 Анализ access-логов и auth
# Топ IP в nginx access.log
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -nr | head -20
# Самые медленные запросы ($request_time)
awk '{print $NF, $7, $9}' /var/log/nginx/access.log | sort -nr | head -20
# Неудачные SSH (Debian/Ubuntu)
grep 'Failed password' /var/log/auth.log | tail -50

🪟 3. Windows: Event Logs и PowerShell

📁 Основные журналы (evtx)
  • System – события ОС и служб
  • Application – приложения
  • Security – аудит (Event ID 4625 – неудачный вход)
  • IIS: %SystemDrive%\inetpub\logs\LogFiles\W3SVC*
⚡ Get-WinEvent – фильтрация на стороне службы
# Системные события за последние 30 минут
Get-WinEvent -FilterHashtable @{LogName='System'; StartTime=(Get-Date).AddMinutes(-30)}
# Ошибки приложений за 2 часа
Get-WinEvent -FilterHashtable @{LogName='Application'; Level=2; StartTime=(Get-Date).AddHours(-2)}
# Неудачные логины (Security, ID 4625) за час
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4625; StartTime=(Get-Date).AddHours(-1)} | Format-List
# Для текстовых логов — аналог tail -f
Get-Content .\app.log -Tail 200 -Wait
# Поиск по каталогу
Get-ChildItem C:\Logs -Recurse -Filter *.log | Select-String -Pattern 'timeout|exception'

🛠️ 4. Инструменты: от локальных до enterprise

📌 Локальные утилиты
  • lnav – консольный лог-вьювер с SQL
  • ripgrep (rg) – молниеносный grep
  • jq – работа с JSON-логами
  • Klogg / LogExpert – GUI для гигабайтных файлов
  • Log Parser 2.2 – SQL-запросы к логам Windows
☁️ Централизованные системы
  • Grafana Loki – легковесный, метки, интеграция с Grafana
  • SigNoz – логи + трейсы + метрики (OpenTelemetry)
  • ELK Stack (Elasticsearch, Logstash, Kibana) – полнотекстовый поиск
  • Graylog – алерты, потоки событий
  • Splunk – корпоративный стандарт для безопасности

⚡ 5. Что реально экономит время

🎯 1. Ограничивайте выборку до чтения
journalctl --since, --until, -u, -p, _PID
🔁 2. Считайте повторы
grep 'error' app.log | sort | uniq -c | sort -nr | head -20
📖 3. Смотрите контекст (-A, -B, -C)
grep -A20 -B10 'panic' app.log
🔄 4. Проверяйте ротацию (gz, старые экземпляры)
zgrep -i 'error' /var/log/myapp/*.gz

Записывайте гипотезы
🔑 6. Добавляйте в приложения request ID / trace ID
grep -Rni 'request_id=abc123' /var/log/
